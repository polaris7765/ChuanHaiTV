## Android TV 影视聚合应用（YuJianTV / 遇见影视 TV）
- 技术选型：Android 原生 Kotlin + AndroidX Leanback 1.0.0 + media3 ExoPlayer 1.3.1（HLS）；理由：Leanback 原生 D-pad 焦点与 10-foot UI，ExoPlayer 直播 m3u8，可编译出真机 APK。RN/Unity 不适合。
- 构建链：Gradle 8.14.3 + AGP 8.11.1 + Kotlin 2.2.0 + JDK 17 / compileSdk 34 / minSdk 23。AGP 8.9.2 配 Kotlin 2.2.0 会产生大量 D8「Kotlin metadata」警告，升到 8.11.1 后清零。
- 目标站 `http://www.yujiannatian.net/` 为赞片CMS（zanpiancms12 模板），HTTP 明文，必须 `usesCleartextTraffic` + `network_security_config`。解析四层：
  1. `/sitemap.html`：`div.layout-box > div.box-title h2` 取大类，`div.sitemap ul > li a` 取分类/类型（实测 5 大类 / 231 项）。
  2. 列表：`#content > li > a.img-pic`（封面取 `img[data-original]`，排除 `pic.png` 占位），`#count` 取总数（注意不要把「当前第 N 页」拼进总数），`#page` 里 `index-N.html` 取总页数；分页 URL = 路径去掉 `.html` 加 `-N.html`，目录型路径加 `index-N.html`。
  3. 详情：`a[id^='#con_playlist_']` 按 id 去重取更完整的播放源全称，`ul#con_playlist_N li a` 取剧集；封面 `.vod-detail-pic img`，简介 `li.detail-info p.ownText()`。
  4. 播放页：正则 `zanpiancms_player\s*=\s*(\{.*?\})\s*;` → JSONObject 的 `url` 即 m3u8。
- 架构要点：所有 href 只存站点相对路径，地址变更时 `SiteConfig.commit` 递增 version 使缓存整体失效；设置页「先 probe（抓 sitemap 并解析）再提交」，失败不改原地址；错误统一为 `SiteError` + `LoadResult` + `StatusFragment`（重试 / 换址 / 恢复默认，均可遥控器聚焦）。

## 电视端启动闪退修复（同一天，用户反馈「显示正在抓取站点分类后崩溃退出」）
- 根因（模拟器 API 34 不复现、低版本电视必崩）：`HtmlParser.parseCategories` 用 `LinkedHashMap.putIfAbsent`，该方法 Android 7.0 / API 24 才有；minSdk 23 设备上抛 `NoSuchMethodError`（属 `Error` 而非 `Exception`），原有 `catch (Exception)` 全部拦不住 → 直接闪退。用 `./gradlew lintDebug` 的 `NewApi` 规则定位。
- 第二个地雷：Jsoup 1.17.2 依赖 `java.util.function` / `java.util.stream`（同样 API 24 才有），D8 默认不做核心库降级。解决：`isCoreLibraryDesugaringEnabled = true` + `coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.5")`，dex 中出现 `j$/util/function/*` backport 类，APK 由 8.9MB 增至 11MB。
- 加固：数据层 `load` 改 `catch (Throwable)` 并归一化 `NoSuchMethodError/NoClassDefFoundError/OOM`；Fragment 协程统一 `guardedLaunch`（`CoroutineExceptionHandler` → 错误页）；`CacheStore`/`ImageLoader` 也 catch `Throwable`（图片解码 OOM 是 Error）；新增 `CrashHandler` 落盘 `files/last_crash.txt`（机型/API/堆栈），下次启动由 `StatusFragment.crash` 展示，用户无需 adb 即可看到根因；状态层 Fragment 用 tag 查找消除异步事务竞态。
- 顺带修 TV 布局缺陷：`fragment_status.xml` 原本固定高度，长文本把底部三个按钮挤出屏幕，改为 message `layout_weight=1` + `maxLines=10`，保证按钮在任意电视屏幕上可聚焦；崩溃摘要把异常首行放最前，避免截断后看不到原因。
- 经验：**lint 的 `NewApi` 必须进常规验证**；`UnsafeOptInUsageError`（media3 @UnstableApi）会沿调用链级联，已在 lint 里降级为 warning，其余 API 检查保持 Error。
- 最终验证：BUILD SUCCESSFUL / lint 零 Error / 7 个单测（新增重复路径去重用例）/ javap 确认 HtmlParser 只剩 `containsKey`+`Map.put` / 模拟器冷启动首页正常（电视剧 72、电影 65、动漫 48 项 + 封面）/ 注入崩溃记录后报告页按钮完整可见且「重试」可清除记录恢复首页。
