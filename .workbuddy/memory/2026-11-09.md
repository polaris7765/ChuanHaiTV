- 封面缓存：`ImageLoader` 加载顺序改为「同步 App icon 兜底 → 内存 LRU → 磁盘 `cacheDir/covers/<MD5(url)>.img` → 短超时网络」；原子写 tmp+rename，>64MB 裁剪到 48MB；熔断只作用于网络阶段。实测 28 个 `.img` 跨多次启动保留。
- 下载：`VideoDownloader` 重写——`enqueue` 立即落 `downloading` 记录；每 2% 节流持久化；HLS 用 `.part`（分片 URL 指纹 + 已完成数 + 总数）append 续传；MP4 用 `SiteHttpClient.openRange()` + `Range` + 206 判断；`DetailFragment.applyDownloadVisual()` 用 `bg_download_progress.xml` 的 `ClipDrawable`(level=progress×100) 做按钮背景填充；`DownloadsFragment` 分「下载中/下载完成」两组 + ProgressBar。

本轮额外修掉的三个实证缺陷（模拟器 root 后查文件 + UI dump 定位）：
1. **下载列表每次进度都 `notifyDataSetChanged()`**：EGL 渲染掉到 ~3fps、界面持续非 idle、「取消」点击被 rebind 吃掉。改为 `submit(newRows, host)` 比对行结构键，结构不变只原地刷新可见条目，不触发 notify。
2. **记录卡在「下载中 100%」**：进程回收时 100% 已落盘但 `done` 未写入。`App.onCreate()` 加 `VideoDownloader.reconcile()` 校正（文件完整→done，否则→paused）；`cancel()` 由删除记录改为标 `paused` 并提供「继续」按钮；`delete()` 复位内存状态避免详情页残留「重试」；两个下载循环每片/每 64KB 检查 `isActive(key)`（同步 OkHttp 不响应协程取消），进度回调开头也加该判断，防止在途分片把 `paused` 覆盖回 `downloading`。
3. **ZMSR 重复卡片 / 状态文案**：见上。
